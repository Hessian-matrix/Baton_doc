# 联调与飞行前验收

## 验收原则

首次联调必须逐项确认。串口有数据、Web 显示正在转发或地面站出现 GPS 图标，都不能单独证明飞控已经正确采用定位信息。所有地面检查先在拆桨条件下进行。

## 1. 基础状态

1. Lite、D20 和飞控供电正常，接线无发热、松动或反向供电。
2. Web 控制台可以正常访问，顶部状态显示运行正常。
3. 在“基础连接”中确认 FCU 串口和波特率。
4. 在“GPS 与 RTK”中确认 RTK 功能已开启，串口和波特率与 D20 一致。
5. 记录 Lite、D20、飞控固件版本和本次配置备份。

## 2. RTK 链路

| 检查位置 | 观察项 | 通过条件 |
| --- | --- | --- |
| D20 | 定位状态 | 定位连续，差分状态满足任务要求 |
| Web 状态首页 | RTK 串口输入 | 已连接并持续更新 |
| Web 状态首页 | 实时频率 | 与 D20 实际定位输出频率接近 |
| Web 状态首页 | 转发延迟 | 稳定且无持续增长 |
| 地面站 | GPS 状态 | fix、卫星数、位置和速度持续更新 |
| 飞控估计器 | Home 与健康状态 | Home 正常建立，无持续 GPS 拒绝或初始化告警 |

D20 设置频率不等于实际输出频率。验收时应同时比较 D20 配置、Web“实时频率”和飞控日志中的接收频率。

## 3. 视觉链路

1. 在“算法与 VIO 控制”中确认“VIO 算法”“里程计输入话题”和“相机安装方向”。
2. 静止时观察位置和速度，不应持续明显漂移。
3. 缓慢向前、向右、向下移动，并小角度偏航，核对飞控显示的轴向、符号和航向变化。
4. 查看地面站状态文本，确认视觉跟踪质量正常。
5. ArduPilot 检查 EKF3 ExternalNav；PX4 检查 EKF2 External Vision 及创新量。

任一轴向错误都必须先修正安装方向或飞控配置，不得进入解锁测试。

## 4. ArduPilot 来源切换

在未解锁状态下完成：

1. 将“EKF 来源切换 RC 通道”拨到 GPS 挡，确认飞控使用 GPS 来源。
2. 拨到视觉挡，确认视觉定位开始工作且飞控切换到对应来源。
3. 观察切换前后位置、速度和航向是否连续。
4. 切回 GPS，确认来源恢复且 EKF 保持健康。
5. 操作“安全模式 RC 通道”，确认其挡位与预期一致后恢复正常位置。

RC 挡位、视觉定位运行和飞控采用视觉是三个不同状态，必须分别确认。

## 5. PX4 融合验证

1. 在 QGroundControl 中确认 GPS 与 External Vision 均持续更新。
2. 检查 `EKF2_EV_CTRL` 和 `EKF2_GPS_CTRL` 已启用任务所需融合项。
3. 通过地面移动确认 local position、速度和航向方向正确。
4. 下载 ULog，确认两类观测被 EKF2 采用，且没有持续 reject 或 failsafe。

## 6. 飞行前检查

- D20 定位质量达到任务要求；需要 RTK 固定解的任务必须确认 fixed。
- Home 已建立，无 `AHRS: waiting for home` 或 PX4 对应初始化告警。
- 罗盘、IMU、遥控器、飞行模式和失效保护均已检查。
- GPS 与视觉静止速度合理，位置无明显跳变。
- 相机安装方向、RTK 外参和视觉轴向已通过地面动作验证。
- “ROS 数据录包”和“RTK 串口原始数据”已开始记录，存储空间充足。
- 首次飞行具备人工接管和切回已验证定位来源的条件。

## 7. 分级飞行

建议按以下顺序逐步扩大测试范围：

1. 拆桨地面动作验证。
2. 系留或安全场地内低高度悬停。
3. 小范围前后、左右、升降和偏航。
4. GPS 与视觉来源切换验证。
5. 检查飞控日志后，再逐步增加高度和距离。

不得从地面验证直接跳到 60 m 飞行。

## 8. 验收记录

| 类别 | 应保存内容 |
| --- | --- |
| 硬件 | Lite、D20、飞控型号，接线端口和安装方向 |
| 配置 | Web 配置截图、飞控修改前后完整参数、D20 配置 |
| 数据 | ROS 数据录包、RTK 原始字节日志、DataFlash 或 ULog |
| 结果 | 每项通过/失败、测试时间、操作者和异常现象 |
