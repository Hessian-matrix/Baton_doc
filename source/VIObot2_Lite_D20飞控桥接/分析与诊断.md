# 分析与诊断

## 排查顺序

定位异常时按以下层级检查：

1. D20 是否正常定位并持续输出。
2. Web 是否显示 RTK 串口输入正常。
3. Web 的 GPS 转发、实时频率和转发延迟是否正常。
4. 飞控是否识别 GPS 与视觉定位。
5. EKF3 或 EKF2 是否实际采用对应观测。
6. 最后再分析飞行控制参数和 PID。

修改配置前先保存 Web 状态截图、参数备份和测试记录，不要用反复修改覆盖现场证据。

## 常见问题

### RTK 串口输入异常

在 Web 的“GPS 与 RTK”中检查：

1. “启用 RTK 输入、NMEA/外参发布及 GPS 转发”（`enable_rtk`）是否开启。
2. “RTK 串口”（`rtk_port`）是否为实际连接端口。
3. “RTK 波特率”（`rtk_baudrate`）是否与 D20 一致。
4. D20 是否正常供电、共地并持续输出定位数据。

仍无法判断时，在首页开始“RTK 串口原始数据”记录，复现后停止并下载。

### Web 显示未转发

确认“RTK 串口输入”正常后，继续检查：

- D20 是否具有有效定位输出，而非只有接收机提示文本。
- “实时频率”是否为 0，“转发延迟”是否持续增长。
- 最近一次修改后是否执行了“保存并重启”。
- 页面顶部运行状态是否正常。

不要通过提高期望频率掩盖无有效定位数据的问题。

### Web 显示正在转发，但飞控没有 GPS

1. 确认飞控 UART 为 MAVLink2 且波特率为 921600 bps。
2. ArduPilot 检查 `GPS1_TYPE` 或实际使用实例是否为 MAVLink GPS。
3. PX4 检查 MAVLink 实例和 `EKF2_GPS_CTRL`。
4. 在地面站检查对应 GPS 实例的 fix、卫星数、位置、速度和 DOP。
5. 下载 DataFlash 或 ULog，确认飞控是否拒绝该观测。

### HUD 有 GPS，但无法建立 Home 或解锁

GPS 图标不等于定位数据满足 Home 初始化。继续检查：

- fix 类型是否满足要求。
- 经纬度、高度、速度、时间和 DOP 是否有效。
- 飞控估计器是否健康，是否存在持续创新拒绝。
- `GPS_PRIMARY`、`GPS_AUTO_SWITCH` 和 EKF 来源是否与实际 GPS 实例一致。

出现 `AHRS: waiting for home` 时，不应通过关闭解锁检查作为正式解决方案。

### 切换视觉来源后没有视觉定位

1. 在 Web“飞控配置”中再次“探测当前配置”。
2. 确认“EKF 来源切换 RC 通道”与遥控器实际通道一致。
3. 在“算法与 VIO 控制”中确认“VIO 算法”“里程计输入话题”和“相机安装方向”。
4. 查看地面站是否有视觉质量或航向对齐提示。
5. 切换后缓慢移动设备，确认飞控视觉位置与速度持续更新。

飞控显示来源已切换，不等于视觉数据已经有效或已被估计器采用。

### RTK 模式摇摆，视觉模式正常

先排除定位输入问题，再调飞控 PID：

1. 检查 Web“实时频率”和“转发延迟”是否稳定。
2. 对比 D20 实际输出频率与飞控日志接收频率。
3. 检查飞控日志中的位置、速度、DOP 和定位状态是否同步且连续。
4. 同时保存“ROS 数据录包”“RTK 串口原始数据”和飞控日志。
5. 只有定位输入确认正常后，才比较 GPS 模式的速度、位置和姿态控制参数。

## 必需诊断资料

提交问题时至少提供：

| 资料 | 获取位置 |
| --- | --- |
| Web 状态截图 | “桥接程序状态”和相关配置分组 |
| Web 配置 | 各普通配置页截图或导出信息 |
| 飞控参数 | Mission Planner 或 QGroundControl 完整导出 |
| 飞控日志 | ArduPilot DataFlash 或 PX4 ULog |
| 视觉与 RTK 记录 | Web“ROS 数据录包” |
| D20 原始数据 | Web“RTK 原始字节日志” |
| 硬件信息 | 接线照片、安装方向、外参测量和设备版本 |

## 证据边界

- “RTK 串口输入”正常：证明 Lite 收到数据，不证明定位内容有效。
- “GPS 转发”正常：证明 Lite 已发送数据，不证明飞控已经采用。
- 地面站出现 GPS：证明飞控识别到 GPS 状态，不证明 EKF 融合健康。
- 飞控提示来源切换：证明来源状态变化，不证明视觉质量合格。
- 最终结论应同时依据 Web 状态、地面站状态、飞控日志和实际运动方向检查。
